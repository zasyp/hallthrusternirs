# Численная схема и API пакета `HallThrusterNIRS`

Документ описывает 1D-3V гибридную PIC/EMHD-модель холловского двигателя,
её дискретизацию, временной цикл, систему адаптивного шага и всё API
пакета: каждая публичная функция имеет краткое описание формул, единиц,
аргументов и места в общей схеме.

Все ссылки на «paper» относятся к препринту Гавриков — Таурский 2021 (статья,
по которой реализована модель); номера уравнений приведены там, где это полезно.

---

## 1. Физическая модель

### 1.1 Геометрия и переменные

- 1D по координате `z ∈ [0, L]`, две скорости `(v_y, v_z)` (азимутальная + осевая).
- Ионы и нейтралы — в `z`, электроны — флюид (только моменты `n_e ≈ n_i`,
  `T_e`, `v_e`).
- Магнитное поле имеет только радиальную компоненту `B_x(z) ≡ H_*`, причём
  `H_* = H_ind + H_ext`, где `H_ext(z)` — аналитический внешний профиль
  (`gaussian_Br` / `lorentzian_Br` / `sech2_Br`), `H_ind(z, t)` — наведённое
  плазменное поле, обновляемое по Фарадею.
- Электрическое поле имеет компоненты `(E_y, E_z)`. `E_y` определяется из
  обобщённого закона Ома (эллиптическая задача), `E_z` — алгебраически по
  уравнению (38) из статьи.
- Полный плотностной ток: `j_y = ∂_z H_*` (Ампер для плазменного тока),
  собственно `j_y` — это «инжектированный + индуцированный» ток в плоскости,
  соответствующей выходному обобщённому закону Ома.

### 1.2 Безразмерные параметры

Безразмерные группы (см. `paper_dimensionless_from_si`):

- `ε  = t_char · ω_ci`, `t_char = L / v_ref` — отношение временных масштабов.
- `κ  = v_A / v_ref` — отношение Альфвéновской скорости к опорной (`κ = 1`,
  если использовать `alfven_reference_scales`).
- `ζ  = k_B T / (m_i v_A²)` — отношение давления к магнитному давлению.
- `ξ  = c √(λ_i λ_e) / (L √(4π ρ))` — гауссова форма (см. `xi_gaussian`).
- `λ_e/λ_Σ = m_e/(m_i + m_e)`, `λ_i/λ_Σ = m_i/(m_i + m_e)`.
- `α  = (m_i/m_Σ) ξ²` — коэффициент в эллиптическом операторе для `E_y`.
- `α0 = κ ξ (m_i/m_Σ) √(m_i/m_e)` — коэффициент Холла в (38).
- `k_I = β₀ · n_ref · t_char` — Дамкёлер ионизации.
- `ν_m0` — Спитцеровская электрон-ионная частота столкновений, выраженная
  в обратных `t_char`.

Все эти величины заносятся в `SimParams` (см. ниже).

## 2. Сетка и дискретизация

- Узловая сетка скалярных полей `z_i = (i-1) h, i = 1, …, M+1` (`h = L/M`).
- Полуузловая сетка `z_{i+1/2} = (i - 1/2) h, i = 1, …, M` для индуцированного
  магнитного поля `H_x_half`.
- Одни и те же CIC-веса используются и при депозите частиц
  (`deposit_particles`), и при обратной интерполяции полей в push'ере
  (`move_particles`) — это гарантирует баланс импульса при усреднении.

Контрольные объёмы для усреднения сделанных «зарядов»: `V_i = h` во внутренних
узлах и `V_i = h/2` в граничных. Это согласуется с граничными добавками веса
ионизированных частиц (`new_particles_ionisation`) и интерпретацией `n_a` как
числа на единицу длины.

## 3. Полная численная схема за один шаг `n → n+1`

Переход за безразмерный шаг `τ = τ^{n+1/2}` выполняется в порядке, реализованном
в `CoreSolver.run_simulation` (один проход цикла `while t < total_time`):

1. **Депозит частиц** (`deposit_particles`).
   Считаем `n_i^n, v_iy^n, v_iz^n, T_e^n` на узлах. PIC-моменты сразу
   сглаживаются Стекловым ядром (`Steklov_smooth`, `radius=1, passes=5`).
2. **Сборка `H_*^n`, `ν_m^n`, `v_H^n`**.
   - `H_x^n` на узлах = интерполяция `H_x_half` + `H_ext`.
   - `ν_m^n = ν_m0 / T_e^{3/2} + α_B ε |H_*|/m_e` (Spitzer + Bohm),
     см. `local_nu_m`.
   - `v_H^n_max = max_i α0 |H_*|/(n c)` — холлова скорость для CFL.
3. **Адаптивный шаг `τ`** — минимум по активному набору ограничений
   (`tau_constraints`): нейтральный CFL, ионный CFL, частота столкновений,
   холловская скорость, см. § 6.
4. **Текущий ток `j^n = ∂_z H_x_half`** (`compute_current`).
5. **Тепловая полу-неявная схема** (`intermediate_temperature`):
   `T_e^{n+1} = T_e^n + τ (Q_coll + Q_ion - (γ-1) T ∂_z v_iz)`. Затем
   `T` на каждой частице обновляется CIC-интерполяцией нового `T_e^{n+1}`.
6. **Адвекция нейтралов** (`neutrals_evolution`): полу-неявный апвинд.
7. **Эллиптический Ом** (`electric_field_solver` с `apply_faraday=false`):
   решаем по `E_y^n` тридиагональную систему (см. § 5.5). `H_x_half` и `j`
   при этом **не трогаются**.
8. **Алгебраический `E_z^n`** (`compute_Ez`): уравнение (38) на одном
   временном слое (`H_x_half^n, j^n, n_a^{n+1}`); добавляется униформный
   разрядный байас `E_z0_dimless + E0_dimless`.
9. **Push частиц** (`move_particles`): подшаговый Boris-предиктор-корректор
   на старом наборе полей `(E_y^n, E_z^n, H_*^n, j^n, ν_m^n)`. Возвращает
   `thrust_step` — выходящий импульс.
10. **Фарадей**:

    `H_x_half^{n+1} = H_x_half^n + τ ∂_z E_y^n` (если `acc_ind=true`),
    либо `H_x_half^{n+1} = τ ∂_z E_y^n` (квазистационарная замыкающая).

    После этого `j^{n+1} = ∂_z H_x_half^{n+1}` и (при необходимости)
    демпфирование `H *= (1 - induced_H_damping)`.
11. **Диагностика и снимки**: пересчитываются `H_total`, `ν_m`,
    параметр Холла `β_e`, обновляется история (`thrust`, `tau`,
    `max|E_z|`, `|H_self|/|H_ext|`, `peak|v_ey|`, `Ey RMS`, …),
    при попадании в `save_times` сохраняется снимок.
12. **Источник новых частиц** (`new_particles_ionisation`) и
    **рекомбинация / выход из канала** (`remove_inactive_particles`).
13. `n_a^n ← n_a^{n+1}`, `t ← t + τ`.

> Важно: смешивания временных слоёв нет — Push идёт на одном наборе полей,
> Фарадей применяется **после** Push'а, а `compute_Ez` пользуется
> `H_x_half^n`, `j^n` и `n_a^{n+1}` (на этом этапе нейтралы уже обновлены).
> Это leapfrog-подобная согласованность.

## 4. Адаптивный временной шаг

Управляется аргументом `tau_constraints` функции `run_simulation`. Активный
набор ограничений и соответствующие предельные шаги:

| Имя              | Формула                                       | По умолч. safety |
|------------------|-----------------------------------------------|------------------|
| `:neutral_cfl`   | `safety · h / v_a`                            | `1.0`            |
| `:ion_cfl`       | `safety · h / max|v_iz|`                      | `0.2`            |
| `:collision`     | `safety / max(ν_m)`                           | `0.5`            |
| `:hall`          | `safety · h / v_H`, `v_H = α0 |H_*|/(n c)`    | `1.0` (можно ослаблять до 2.0) |

Преднастройки:

- `:full` — все четыре (по умолчанию).
- `:fluid_only` — без `:hall` (оправданно, т.к. часть холла обрабатывается
  полу-неявно в эллиптическом Ом-солвере).
- `:none` — только `total_time - t` (отладка).
- Один `Symbol` или `Tuple/Vector` из `_TAU_NAMES = (:neutral_cfl, :ion_cfl,
  :collision, :hall)` — явный список.

Если выбранный `τ < tau_min_floor`, или невалиден, происходит «recovery»:
`τ = min(1e-8, 0.01 h / max|v_iz|, h/v_a, total_time - t)`. Каждый шаг
запоминается лимитирующее ограничение, в финале выводится таблица их долей.

> Электронно-циклотронный CFL `1/ω_ce` намеренно отсутствует: электроны
> не двигаются явным push'ером, а входят только в эллиптический Ом —
> ограничивать `τ` по `ω_ce` физически неоправданно.

## 5. Подробное описание модулей и функций

### 5.1 `HallThrusterNIRS.PartCount`

Контейнерные структуры данных.

- `Particle(z, vy, vz, T, q, active)` — одна PIC-макрочастица.
- `Counters(nan, exited_right, reflected_left)` — диагностические счётчики
  push'ера.
- `SimParams(; …)` — все безразмерные параметры модели и численной схемы.
  Ключевые поля задокументированы в docstring структуры; конструктор
  допускает только `collision_model ∈ (:spitzer, :constant)`.

### 5.2 `HallThrusterNIRS.MagneticField`

Аналитические профили внешнего радиального поля и оценка градиентного
масштаба:

| Функция                                        | Что считает                                      |
|------------------------------------------------|--------------------------------------------------|
| `gaussian_Br(z, B_max, z0, σ)`                 | `B_max · exp(-(z-z0)²/(2σ²))`                    |
| `gaussian_dBr_dz(...)`                         | производная `dB/dz`                              |
| `normalized_gradient_Br(...)`                  | `(1/B_max) dB/dz`                                |
| `lorentzian_Br(z, B_max, z0, w)`               | `B_max / (1 + ((z-z0)/w)²)`                      |
| `lorentzian_dBr_dz(...)`                       | производная Лоренцева профиля                    |
| `sech2_Br(z, B_max, z0, w)`                    | `B_max · sech²((z-z0)/w)`                        |
| `sech2_dBr_dz(...)`                            | производная sech²                                |
| `compute_Br_profile(z_grid, B_max, z0, σ; model=:gaussian)` | возвращает `(; Br, dBr_dz, grad_Br)` по выбранной модели |
| `estimate_LB(σ; model)`                        | характерная длина градиента поля                 |

`H0_func` в `SimParams` обычно строится как замыкание над одной из этих
функций и интерполируется через `H_ext_at_nodes` в каждом шаге.

### 5.3 `HallThrusterNIRS.NumericalFunctionsSPT`

Базовые алгоритмические инструменты:

- `solve_tridiagonal(a, b, c, d)` — алгоритм Томаса для системы
  `a·x_{i-1} + b·x_i + c·x_{i+1} = d_i`. Используется в эллиптическом
  Ом-солвере (диагонально доминирующий оператор).
- `interpolation_weights(x, x_grid)` — CIC-веса `(k0, k1, w0, w1)` на
  равномерной сетке. Точки вне `[x_grid[1], x_grid[end]]` зажимаются
  на ближайшую границу.
- `smooth_field(f, window)` — равномерное усечённое усреднение через
  префиксные суммы (`O(n)` независимо от `window`). В solver'е сейчас не
  используется, оставлено для post-processing'а.
- `Steklov_smooth(f, radius=1, passes=5; boundary=:reflect)` — формула (43)
  из статьи: `f̂(z) = (1/2η) ∫_{z-η}^{z+η} f̃(x) dx`, где `f̃` — чётная
  периодически продолжённая функция. На сетке: `(2 radius + 1)`-точечное
  усреднение с отражением индексов на границах. Параметры по умолчанию
  совпадают с рекомендацией статьи (5 проходов).
- `Steklov_smooth_clamped(f, radius=1, passes=5)` — формула (44):
  усреднение в укороченных интервалах `[max(z-η,0), min(z+η,L)]` без
  отражения. Используется, когда выбран `boundary=:clamped`.

### 5.4 `HallThrusterNIRS.PlasmaDynamics`

Замкнутая EMHD-фаза.

#### `local_nu_m(ν_m0, T_loc, model, H_loc, alpha_B, ε, me) -> Float64`

Локальная электронно-импульсная частота столкновений:

```
ν_e = ν_base(T) + α_B · ω_ce_dim,    ω_ce_dim = ε · |H_*| / m_e,
ν_base = ν_m0 / (T^{3/2} + T_FLOOR^{3/2})   (model = :spitzer),
ν_base = ν_m0                                (model = :constant).
```

`T_FLOOR = 0.01` — нижний порог температуры для регуляризации Спитцера.
`α_B = 1/16` восстанавливает классический Бомовский предел (Hagelaar 2002,
Boeuf–Garrigues).

#### `H_star_channel_nonneg(H_ind_plus_ext) -> Float64`

Тождество (исторически — клиппинг к нулю; теперь оставлено как
no-clip pass-through, чтобы не нарушать Фарадей). Само имя сохранено для
совместимости с обращениями.

#### `neutrals_evolution(n_a_new, n_a_old, n_ion, τ, v_a, kI, h, n_source)`

Адвекция нейтралов с явным апвиндом и неявной ионизационной откачкой:

```
n_a^{n+1}_i = (n_a^n_i - v_a τ (n_a^n_i - n_a^n_{i-1})/h) / (1 + τ kI n_i),
n_a^{n+1}_1 = n_source                  (граница входа),
n_a^{n+1}_i = max(n_a^{n+1}_i, 0).
```

Если `v_a τ / h > 1`, выводится `@warn` (нейтральный CFL уже встроен в
адаптивный шаг, поэтому в нормальных запусках он не должен срабатывать).

#### `intermediate_temperature(T_new, T_old, n, vz, j, n_a, τ, γ, mi, me, ν_m0, kI, h; …)`

Явное обновление электронной температуры:

```
T^{n+1} = T^n + τ [Q_coll + Q_ion - (γ-1) T^n ∂_z v_iz],
Q_coll  = (γ-1) (m_i/m_Σ) ν_m(T,|H_*|) j² / n_safe,
Q_ion   = -(γ-1) k_I T^n n_a.
```

Здесь `n_safe = n + max(n_reg_min, N_FLOOR)` стабилизирует Джоулев нагрев в
зонах с малой плотностью. Результат зажимается в `[T_FLOOR, T_cap]`,
граничные узлы — Нейман: `T[1] = T[2]`, `T[M+1] = T[M]`. Опциональные
аргументы `H_total`, `alpha_B`, `ε`, `me` подключают Бомовскую часть `ν_m`.

#### `compute_current(j, H_x, h)`

Центральная разность по полу-узловому `H_x`:

```
j_i = (H_x^{half}_i - H_x^{half}_{i-1}) / h,   j_1 = j_{M+1} = 0.
```

Внешнее поле в `j` не учитывается — оно описывает «внешние» катушки и не
является плазменным током.

#### `electric_field_solver(E_y, H_x_old, j_old, n, vz, T, τ, α, ν_m0, h, x_grid, H0_func, bc_type, v_a, c_inv; …)`

Эллиптический Ом + опциональный Фарадей за один проход.

Тридиагональная схема (paper §3, Eq. (36)):

```
A = α / (n h²),                B = ν_m τ / (2 h²),
C = v_z τ c_inv / (4 h),       D = (α τ / (2 n h²)) ∂_z v_z,
a_i = -A - (B + D) - C,
b_i = 1 + 2A + 2(B + D),
c_i = -A - (B + D) + C,
d_i = ν_m j_old + (α/n) j_old ∂_z v_z + (α/n) v_z ∂_z j_old - H_*^n v_z c_inv,
```

С граничным условием `bc_type = :j0`:

```
E_y[1]   = (-H_*^n + (α/n) j_old[2]/h)         · v_z[1]   c_inv,
E_y[M+1] = (-H_*^n + (α/n) (-j_old[M]/h))      · v_z[M+1] c_inv,
```

(уравнения (38) на границах после подстановки `j_old` через
односторонний диффер, см. paper §3, граничные условия для эллиптической
части). После решения тридиагональной системы:

- если `apply_faraday = false` (используется в `run_simulation`):
  возвращается `(E_y, H_x_old, j_old)` — Фарадей **не** применяется;
- если `apply_faraday = true`:
  `H_x^{new} = H_x^{old} + τ ∂_z E_y` (или `H_x^{new} = τ ∂_z E_y` при
  `advance_induced_H = false`); затем `compute_current(j_new, H_x^{new})`
  и `(E_y, H_x^{new}, j_new)` возвращаются.

Внешнее поле даётся либо `H_ext_at_nodes`, либо `H0_func.(x_grid)`.

#### `compute_Ez(Ez, H_x_old, H_x_new, j_old, j_new, n, T, vy, n_a_new, n_a_old, α0, ζ, kI, va, h, λ_e_λΣ, β_Ez_coef, c_inv, τ, x_grid, H0_func, n_floor; …)`

Алгебраическое уравнение для осевого поля (paper Eq. (38)):

```
E_z = (H_*/c) v_iy
    - (λ_e/λ_Σ / ε) k_I n_a v_a
    - (α_0 / n_safe) H_* j_y
    - (ζ α_0 / n_safe) ∂_z (n T_e).
```

Особенности реализации:

- Если `H_x_old === H_x_new` и `j_old === j_new` (типичный вызов из
  драйвера на одном слое), полусумма не считается и не аллокируется.
- Сглаживание Стеклова применяется только к `n·T` и `v_iy`. **Ток `j` не
  сглаживается**: иначе нарушалась бы согласованность с
  `j = ∂_z H` (curl-производная не должна терять локальную структуру).
- Опциональные буферы `Ez_termK` сохраняют каждый из четырёх вкладов для
  диагностики (см. `print_physicality_report`).
- `H_*` на узлах строится интерполяцией `H_x_half` и добавлением
  `H_ext_at_nodes` (предпочтительно — кэш) или `H0_func.(x_grid)`.
- Если в каком-либо узле получилось `Inf`/`NaN`, оно занулится.

### 5.5 `HallThrusterNIRS.ParticleMovementSPT`

Все операции, изменяющие список `particles`.

#### `deposit_particles(particles, x_grid, n, v_y, v_z, T, h, n_vy, n_vz, n_T)`

CIC-сборка плотности и моментов:

```
n[k]      += q · w_k,
n_vy[k]   += q · w_k · v_y,
n_vz[k]   += q · w_k · v_z,
n_T[k]    += q · w_k · T_p,
```

затем нормировка `v_y[i] = n_vy[i]/n[i]` (если `n[i] > N_FLOOR`, иначе ноль и
`T = T_FLOOR`) и контроль объёма `n[i] /= V_i`. Возвращает `(n, v_y, v_z, T)`,
но всё пишется in place.

#### `move_particles(particles, E_y0, E_y1, E_z0, E_z1, H_x0, H_x1, j0, j1, ν_m0, ν_m1, x_grid, x_half, τ, h, ε, mi, c_inv, H0_func, counters) -> thrust_step`

Подшаговый Boris-style предиктор-корректор по характеристикам ионов
(paper system (11), безразмерно):

```
∂v_y/∂t = ε (E_y + (H_*/c) v_z - ν_m j_y),
∂v_z/∂t = ε (E_z - (H_*/c) v_y),
∂z/∂t   = v_z.
```

Подразбиение шага: `N0 = max(1, ceil(τ |v| / (0.25 h)))` — подсшаг не
превосходит четверти ячейки. Поля линейно интерполируются между
старым (`*0`) и новым (`*1`) слоями; в текущем драйвере оба указателя
показывают на один и тот же массив, что делает push однослойным.

Граничные правила:

- Правый край `z ≥ L`: частица деактивируется, к `thrust_step` добавляется
  `m_i q max(v_z, 0)` (вклад в осевой импульс), `counters.exited_right` ++.
- Левый край `z ≤ 0`: поглощается (`counters.reflected_left ++`); масса
  возвращается в систему через граничный источник `n_a(0) = n_a_left`.
- NaN-скорости: частица деактивируется, `counters.nan ++`.

Возвращаемое `thrust_step` — суммарный осевой импульс, выходящий за `τ`.
Драйвер делит его на `τ` и сохраняет как мгновенную тягу.

#### `new_particles_ionisation(particles, n_a_new, n_ion, x_grid, τ, kI, v_a, T_ion; charge_factor=1.0)`

Спавним новые частицы согласно ионизационной плотности:

```
q_new = charge_factor · τ · n_a · n_i · k_I · V_i,
```

(`V_i = h/2` на границах, `h` внутри). Новые частицы получают
`(v_y, v_z) = (0, v_a)` и `T = T_ion`. Если `q_new < MIN_PARTICLE_MASS = 1e-8`,
вклад отбрасывается, чтобы не порождать «хвост» микро-частиц.

#### `remove_inactive_particles(particles, L, τ, kR)`

Объёмная рекомбинация: каждая активная частица деактивируется с вероятностью
`P_rec = min(1, kR τ)`; частицы, ушедшие за `[0, L]`, тоже метятся как
неактивные. После пометки `filter!` сжимает массив. Это единственный
механизм усадки списка частиц, балансирующий ионизационный рост.

## 6. Граничные условия

| Поле / уравнение      | Левая граница (`z = 0`)                       | Правая граница (`z = L`)                 |
|-----------------------|-----------------------------------------------|------------------------------------------|
| `n_a` (нейтралы)      | Дирихле: `n_a = n_source = n_a_left`          | Свободный апвинд (адвекция наружу)       |
| `T_e`                 | Нейман: `T[1] = T[2]`                         | Нейман: `T[M+1] = T[M]`                  |
| `E_y` (Ом)            | `j[1] = 0` ⇒ закрытая формула на `E_y[1]`     | `j[M+1] = 0` ⇒ закрытая формула на `E_y[M+1]` |
| `j` (Ампер)           | `j[1] = 0`                                    | `j[M+1] = 0`                             |
| Частицы               | `z ≤ 0`: поглощение, `reflected_left++`       | `z ≥ L`: уход (вклад в тягу), `exited_right++` |

Левая стенка катода трактуется как идеальный поглотитель: ион аннигилирует,
а соответствующая «масса» возвращается через инжекцию нейтрала
(`n_a(0) = n_a_left`) и ионизационный источник.

## 7. Сглаживание

Сглаживание Стеклова применяется **только** к PIC-моментам сразу после
депозита (раньше прежнюю реализацию также сглаживала `E`, `H`, `j`, что
портило согласованность Ампера / Фарадея — теперь это убрано).

- `steklov_pic_half_width = 1`, `steklov_pic_passes = 5`,
  `steklov_pic_boundary = :reflect` — рекомендованные значения статьи
  (формула (43)).
- При желании можно переключить на `:clamped` (формула (44)).

Поля `E_y`, `H_x_half`, `j`, термы `E_z_termK` — **не сглаживаются**.

## 8. Размерное представление

Полная цепочка для построения SI-графиков:

```
CharacteristicScalesSI ──► paper_dimensionless_from_si ──► SimParams (через sim_from_si)
        │
        └─► si_plot_physical_scales(scales, Hext_dim_max) = (; z_m, n_m3, v_ms, …)
                │
                └─► DimensionalScales(...) ──► plot_results_dimensional
```

Размерные множители:

| Величина | Множитель                          |
|----------|------------------------------------|
| `z`      | `z_m = L_m`                        |
| `t`      | `t_s = L_m / v_ref`                |
| `n`      | `n_m3`                             |
| `v`      | `v_ms = v_ref`                     |
| `T_e`    | `Te_eV = k_B T_K / e`              |
| `E`      | `E_vm = v_ms · B_t`                |
| `j`      | `j_am2 = e · n · v`                |
| `H_*`    | `B_t = |B| / max(H_dimless)`       |
| `ν`      | `nu_s = v_ms / z_m`                |
| `Thrust` | `thrust_n = m_i · n · A · v_ref²`  |

Если `L ≠ c/ω_pi` (ионная скиновая толщина), плазменная шкала тока `e n v`
и шкала Ампера `B/(μ0 L)` различаются. Драйвер выводит коэффициент
`current-scale consistency = (B/(μ0 L)) / (e n v_ref)` — это диагностика
несоответствия выбранной нормировки.

## 9. Ключевые предупреждения и выходы по физике

1. **Не обнуляйте `H_x_half` в начале шага.** Это сломает аккумуляцию
   индуцированного поля Фарадея. В драйвере явно нет `fill!(H_x_half, 0)`.
2. **Не сглаживайте Maxwell-поля.** Сглаживание `E`, `H`, `j` приводит к
   потере согласованности `j = ∂_z H` и `∂_t H = -∂_z E`.
3. **Holl CFL обязателен**, если `α0 |H_*|/(n c)` сравним или превосходит
   `v_a` или `max|v_iz|`. Отключать `:hall` имеет смысл только в режиме
   «чистого флюида».
4. **`v_ey` — диагностика, не динамическая переменная.** Хранится как
   `-j/(e n_e)` (электронный Холловский дрейф), а не как «ион + поправка».
5. **Гирочастотный CFL** в адаптивном шаге не нужен — электроны не
   двигаются явно, ограничение `1/ω_ce` непосредственно физически
   неоправдано в гибридной модели.
6. **Регуляризация плотности** обязательна: `n_safe = n + max(n_reg_min,
   N_FLOOR)`, где `n_reg_min = max(0.01 · n_a_old, n_floor_physical)` —
   иначе Джоулев нагрев и Холловский член диверге́нируют в разреженных
   зонах.

## 10. Пример настройки

См. `examples/spt70_krypton.jl`. Кратко:

- Калибруется `CharacteristicScalesSI` под SPT-70 / криптон.
- Берутся Альфвéновские опорные масштабы (`alfven_reference_scales`).
- `M_GRID = 100`, `N1_MAC = 50`, `T_END = 30.0` — параметры,
  обеспечивающие адекватное разрешение Дебая (≈ 8.5 λ_D на ячейку),
  достижение квазистационара (≈ 7 ионных времён пролёта) и приемлемую
  стоимость.
- `tau_constraints = :full`, `tau_hall_safety = 2.0` — все четыре CFL
  активны, Холловская безопасность ослаблена с учётом полу-неявности
  эллиптического Ом-солвера.
- `save_times = [T_END·0.7, T_END·0.85, T_END]` — снимки в зоне
  стационара.

После запуска в `output/figures/spt70_krypton/` появляются `profiles_*.png`
(размерные и безразмерные), `diagnostics_*.png` и сглаженный график тяги.
